## 调研：导出 ggb/TikZ + 图片上传视觉理解（仅研究，未改代码）

- 画板是**本地 vendor 的 GeoGebra 5.0 web3d**（`public/geogebra/HTML5/5.0/web3d/`），不是 CDN。
- 反查 `09491D314B977D146A653DB7D7FBCEFA.cache.js` 确认 applet 上实际存在：
  - `getBase64()`：无参调用**同步**返回 base64 编码的标准 .ggb（内部用内置 `window.fflate.zipSync` 打包），参数 `(a,b)` 中 `b===false/true` 走同步、`b` 或 `a` 为函数走异步回调。
  - `exportPGF(callback)`、`exportPSTricks(callback)`：`_.exportPGF=function(a){Yxj(...,new bIn(a))}`，`bIn` 是 `{this.g=a}` 回调包装，`Yxj` 走 `Rc(1,...)` 异步调度。**官方文档未列出 PGF/TikZ 导出 API**，菜单里有 `PGF/TikZ (.txt)` 条目。是否真能拿到字符串需浏览器实机验证。
  - 另有 `exportSVG(cb|filename)`、`exportPDF`、`getPNGBase64`、`getFileJSON`、`getLaTeXString`(对象值的 LaTeX，不是 TikZ)、`getAllObjectNames/getObjectType/getXcoord/getYcoord/getColor/getValueString` 等对象检视 API。
- `src/geogebra.ts` 目前只暴露 `getXML()`，未接出任何导出能力。
- EdgeOne **Cloud Functions 请求 body 上限 6 MB**（Edge Functions 1 MB，Models 网关 25 MB）→ 图片必须前端压缩。
- 默认模型 `@makers/deepseek-v4-flash` 是文本模型；Makers 网关内置模型列表未标注视觉。图片功能前提是绑定/配置视觉模型（网关自费厂商模型最省事，仍是 `ai-gateway.edgeone.link`，白名单已含）。
- AI SDK v6 (`ai@6.0.287`) `UserContent = string | Array<TextPart|ImagePart|FilePart>`，`ImagePart = {type:'image', image: DataContent|URL, mediaType?}`；OpenAI provider 会转成 `image_url` data URL，现有 `proxyFetch` + 云函数转发链路无需改造。
- 结论：两个功能都**不需要新增 npm 依赖**。

## 修复：画板溢出 / 分栏不可拖、.ggb 桌面版打不开（已完成，双平台部署 + 推送）

- **布局根因**：`.main` 原本写死 `grid-template-columns: 1.4fr 1fr`，中间没有任何可拖拽手柄；同时 `mountGeoGebra` 只在注入时读一次容器像素宽高，之后窗口缩放 / 工具栏折行 / 提示条出现时 canvas 保持旧尺寸，溢出盖住聊天区。截图中斜着的白色菱形是 3D 视图 xy 平面（视角旋转），不是布局 bug。
- **分栏实现**：`--split` 百分比三列 grid（默认 58%，范围 25–78%）、常驻可见把手、pointer 拖动时全屏遮罩（否则 GeoGebra 的 canvas/iframe 吞掉 move）、双击/Enter/Home 重置、方向键微调、localStorage `geochat-web-v3-split`。窄屏 ≤900px 转上下布局并隐藏分隔条。
- **`setSize` 的重要坑（实测）**：`api.setSize(w,h)` 会给 `#ggb-container` 写 inline `width/height`（传 600×400 却写成容器旧值），并把内部视图缩到错误尺寸，清 inline 也恢复不了；但只派发 `resize` 事件又不足以让内部 canvas 重算。**最终组合**：`.ggb-container { width:100% !important; min-width:0; overflow:hidden }` 锁住容器宽度（压过 GeoGebra 写回的 inline 宽度，打破「容器不缩→画板不缩」死循环）+ `ResizeObserver` → 清 inline → `setSize` 重算内部视图 → 派发 `resize`。
- **另一坑**：`pointerdown` 上 `preventDefault()` 会抑制浏览器生成 `dblclick`，双击重置必须自己在 pointerdown 里按时间差判断；防选中改由 `body.is-resizing` 与 `touch-action:none` 承担。

## 参考项目调研：GeoTikTrim（ggb-tikz-code-filter-main，GPL v2）—— 只研究未改代码

- 项目性质：浏览器扩展 + 单文件网页版，做两件事：① 解析 GeoGebra `exportPGF` 原生产物并**重写**成干净 TikZ（`extension/filter.js` 902 行）；② 截图 → AI 识别 → `evalCommand` 注入 GeoGebra（`prompt.js` 40+ 条指令语法）。许可 **GPL v2**，我们是 **MIT**。
- **实测结论一：它的 filter.js 能直接处理我们引擎的产物**（我们 GeoGebra 5.0 web3d 的 PGF 格式与它假设的完全一致：点 `circle(2.5pt)` + `node{$A$}`、线段 `--`、圆 `circle(2cm)`、`\clip(...) rectangle(...)` + `plot(\x,...)`、角度 `shift={...} -- arc -- cycle`）。把它的 filter.js 注入我们页面后确实跑出了规整结果。
- **实测结论二：它的 filter 有 4 个真实缺陷**：① 点标签按出现顺序配对 → 把对象标签（角度 g、线 f/h、圆 c）误当点标签，产出假点 `\coordinate (g) at (5.38,14.472)`；② 丢弃 `\definecolor`，所有元素变黑；③ 只输出 tikzpicture 片段（需自行补 preamble）；④ 正则与 GeoGebra 版本强绑定。
- **实测结论三（对我们更重要）：GeoGebra 5.0 的 `exportPGF` 在特定组合下会漏对象**。组合 A（3 线段）/B（+角度）/C（+角度+圆）都完整；但组合 E（3 线段 + 圆 + 角度 + 函数 + Point）**丢了 `Segment(A,B)`**。我们 `normalizeTikZ()` 是原样透传引擎产物 → 漏绘会直接进用户导出的 .tex；`buildTikZFallback()`（对象快照）不受影响。
- **结论/建议**：① 不抄代码（GPL copyleft 会要求我们整体转 GPL v2），只借鉴思路并 clean-room 重写；② 最高性价比是**视觉提示词**（GeoGebra 指令语法属官方事实，可自行重写），直接提升读图作图准确率；③ TikZ 导出建议改成「对象快照为主 + 原生 PGF 兜底」或加「对象覆盖校验」；④ 借鉴其预置服务商清单做 UI 下拉；⑤ 借鉴其 `test/test.tex` + `test.pdf` 的编译验证闭环（本机无 LaTeX，需装 TeX Live 或走 CI）。

### 真正的三个 bug（全部由本项目实测定位）
1. **同名覆盖（图形消失的元凶）**：GeoGebra 给无名对象自动分配单字母标签（`Segment(A,B)`→`f`、`Segment(B,C)`→`g`、多边形边→`a`/`b`/`c_1`）。模型输出的 `f(x)=…` 会**静默顶掉**同名线段，对象总数不变（名字被复用）→ 画面少一条线却毫无迹象。
   - 修复：执行**每条**命令前检查它要定义的名字，撞上自动标签（`/^[a-z](_\d+)?$/`）就先给旧对象改名让路，新名用 `ggbauto1` 这类**避开 GeoGebra 函数名空间**的形式；显式名（A/B/alpha）允许覆盖并记录。
   - 必须是**逐条**检查：冲突常发生在同一批命令内部（先 Segment 得 f，后面 f(x)= 撞上）。
2. **样式命令假失败 → 整板回滚（画板突然全清空）**：`SetLineStyle`/`SetColor`/`SetLineThickness`/`ShowLabel`/`SetVisibleInView`/`Rename` 的 `evalCommand` **恒返回 false 但副作用完全生效**（实测 getLineStyle 0→1、getColor→#FF0000、PGF 出现 `dash pattern=on 1pt off 1pt`）。旧逻辑把 false 当失败 → `restoreOnError` 触发**整板 setXML 回滚** → 画面全空。
   - 修复：脚本命令按类型豁免布尔判定；赋值命令改为「false 但对象存在即成功」；**只有整批全失败才回滚**，个别失败保留已画图形并把清单回灌模型。
3. **TikZ 降级生成器在中文环境下本就失效**：applet 的 `getDefinitionString()`/`getCommandString()` 返回**本地化字符串**（中文环境：「线段AB」「圆周(C, 1.5)」），旧实现按英文正则解析端点 → 只能画出点，画不出线段/圆。只有 `getXML()` 里是英文（`<command name="Segment"><input a0="B" a1="C"/><output a0="t"/></command>`）。
   - 修复：新增 `src/lib/tikz.ts`，从 XML 还原英文定义。
   - 注意：`<input a0="B" a1="C"/>` 是**一个元素带多个属性**，正则必须逐属性取。

### 踩坑：GeoGebra 改名命令的形态（实测三种）
- `Rename("s","x")` → **错**：引号让 GeoGebra 当字符串字面量，**新建一个 text 对象**，原线段纹丝不动（且类型变 text，极易误判成"改名成功"）。
- `Rename(s,"x")` → 对（对象名不加引号）。
- `api.renameObject("s","x")` → 对且最直接，**本项目采用**，每次改名后回读对象列表校验。
- 改名目标**不能是 `f1`/`g1`**：那属于 GeoGebra 函数名空间，线段会被变成 text 而消失。
