## 调研：导出 ggb/TikZ + 图片上传视觉理解（仅研究，未改代码）

- 画板是**本地 vendor 的 GeoGebra 5.0 web3d**（`public/geogebra/HTML5/5.0/web3d/`），不是 CDN。
- 反查 `09491D314B977D146A653DB7D7FBCEFA.cache.js` 确认 applet 上实际存在：
  - `getBase64()`：无参调用**同步**返回 base64 编码的标准 .ggb（内部用内置 `window.fflate.zipSync` 打包），参数 `(a,b)` 中 `b===false/true` 走同步、`b` 或 `a` 为函数走异步回调。
  - `exportPGF(callback)`、`exportPSTricks(callback)`：`_.exportPGF=function(a){Yxj(...,new bIn(a))}`，`bIn` 是 `{this.g=a}` 回调包装，`Yxj` 走 `Rc(1,...)` 异步调度。**官方文档未列出 PGF/TikZ 导出 API**，菜单里有 `PGF/TikZ (.txt)` 条目。是否真能拿到字符串需浏览器实机验证。
  - 另有 `exportSVG(cb|filename)`、`exportPDF`、`getPNGBase64`、`getFileJSON`、`getLaTeXString`(对象值的 LaTeX，不是 TikZ)、`getAllObjectNames/getObjectType/getXcoord/getYcoord/getColor/getValueString` 等对象检视 API。
- `src/geogebra.ts` 目前只暴露 `getXML()`，未接出任何导出能力。
- EdgeOne **Cloud Functions 请求 body 上限 6 MB**（Edge Functions 1 MB，Models 网关 25 MB）→ 图片必须前端压缩。
- 默认模型 `@makers/deepseek-v4-flash` 是文本模型；Makers 网关内置模型列表未标注视觉。图片功能前提是绑定/配置视觉模型（网关自费厂商模型最省事，仍是 `ai-gateway.edgeone.link`，白名单已含）。
- AI SDK v6 (`ai@6.0.287`) `UserContent = string | Array<TextPart|ImagePart|FilePart>`，`ImagePart = {type:'image', image: DataContent|URL, mediaType?}`；OpenAI provider 会转成 `image_url` data URL，现有 `proxyFetch` + 云函数转发链路无需改造。
- 结论：两个功能都**不需要新增 npm 依赖**。
