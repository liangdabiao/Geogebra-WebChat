## 一、「图形莫名消失」的两个根因与修复

这两个问题在浏览器里都表现为「画着画着少了一条线」，已逐条实测定位并修复。

### 1. 同名覆盖（真正的元凶）

GeoGebra 会给无名对象自动分配标签：`Segment(A,B)` 得到 `f`，`Segment(B,C)` 得到 `g`，多边形的边得到 `a`、`b`、`c_1`。而模型几乎必然会输出 `f(x)=…` 这类函数定义——**函数名 `f` 会静默顶掉那条线段**，对象数量甚至不变（名字被复用），所以画面上只是"少了一条线"，很难察觉。

修复：执行**每一条**命令之前检查它要定义的名字，若撞上一个自动标签就先给旧对象改名让路（样式、依赖关系都保留，新名字用 `ggbauto1` 这类避开 GeoGebra 函数名空间的形式），并在对话里提示「为避免同名覆盖，已自动重命名：f → ggbauto1」。显式命名（模型自己写的 `A`、`B`、`alpha`）允许覆盖，那是模型的有意行为。

实现位置：`src/geogebra.ts` 的 `protectNameBeforeCommand()` / `renameObjectSafe()`。

> 顺带说明：`Rename("s","x")` 这种**带引号**的形式是错的——GeoGebra 会把 `"s"` 当字符串字面量，结果新建一个 text 对象、原对象纹丝不动。正确写法是 `Rename(s,"x")` 或 applet 的 `api.renameObject("s","x")`，本项目用的是后者。

### 2. 样式命令被误判为失败 → 整板回滚

GeoGebra 的 `evalCommand` 对 `SetLineStyle` / `SetColor` / `SetLineThickness` / `ShowLabel` / `SetVisibleInView` / `Rename` 这类脚本命令**一律返回 `false`**，但副作用完全生效（实测 `SetLineStyle(s,1)` 让 `getLineStyle` 从 0 变成 1，PGF 里也确实出现 `dash pattern=on 1pt off 1pt`）。旧版逻辑把 `false` 当成执行失败，于是**一条样式命令就会触发整块画板回滚**，用户看到的现象是"刚画好的图突然全没了"。

修复：脚本/样式命令不再按布尔返回值判失败；赋值命令改为「返回 false 但对象确实存在就算成功」；并且**只有整批命令全部失败才回滚**，个别命令失败时保留已画出的图形，把失败清单回灌给模型让它自己下一轮修正。

实现位置：`src/geogebra.ts` 的 `runCommand()` 与 `executeCommands()`。

```ts
function runCommand(api: any, cmd: string): boolean {
  let ret: unknown;
  try { ret = api.evalCommand(cmd); } catch { return false; }
  if (ret === true) return true;
  if (SCRIPT_COMMAND.test(cmd)) return true;          // 脚本命令：false 但副作用生效
  const name = definedObjectName(cmd);
  if (name && typeof api.getAllObjectNames === "function") {
    try {
      return Array.from(api.getAllObjectNames() as Iterable<unknown>)
        .some((n) => String(n) === name);
    } catch { return false; }
  }
  return false;
}
```

### 3. 曾经的一个错误结论（已废）

**❌ 已废：「引擎 PGF 会漏对象」** —— 这个结论是测试假象。

当时用 `api.evalCommand("Reset")` 清场，但 **Reset 未生效**导致对象累积，看起来像"同一条线段被画了 4 遍"。真实丢图原因就是上面的同名覆盖。改为「每个场景刷新页面」重测后确认，引擎 PGF 对画板是忠实的。

**教训**：清场不可靠时，用"刷新页面"重建场景，别用 `Reset`。

## 二、TikZ 生成器为什么必须读构造 XML

applet 的 `getDefinitionString()` / `getCommandString()` 返回的是**本地化字符串**（中文环境下是「线段AB」「圆周(C, 1.5)」），按英文正则解析端点在中文下必然失效——这正是旧版降级生成器只能画出点、画不出线段的原因。

只有 `getXML()` 里的定义始终是英文：

```xml
<expression label="f" exp="f(x) = x^(2) / 3 - 2" type="function"/>
<command name="Segment"><input a0="B" a1="C"/><output a0="t"/></command>
```

**坑**：`<input a0="B" a1="C"/>` 是**一个元素带多个属性**，正则若按"一属性一元素"解析会得到 `s = Segment`（缺 `A,B`），导致期望边集合为空。正确写法是逐属性提取：

```ts
for (const im of inner.matchAll(/<input\s+([^>]*?)\/>/g)) {
  for (const am of im[1].matchAll(/a\d+="([^"]*)"/g)) inputs.push(xmlUnescape(am[1]));
}
```

实现位置：`src/lib/tikz.ts` 的 `parseConstructionXml()` / `resolveDefs()` / `expectedGeometry()` / `parsePgfGeometry()` / `diffGeometry()` / `patchPgfWithMissing()`。

**覆盖校验路径**（已用确定性单测验证）：

- 真实 XML/PGF/对象快照下：`expected edges = ['0,0|4,0','2,3|4,0','50,50|60,50']`、`expected circles = ['2,3|1.5']`
- 人为删掉 `\draw (50,50)--(60,50);` 后 → `missing=1`
- 自动补齐后 → `added=1, stillMissing=0`

## 三、GeoGebra applet 的几类坑

### 改名目标不能落在函数名空间

`f` / `g` / `h` / `f1` / `g1` 属 GeoGebra 的函数名空间。把线段改到这些名字上，**线段会被转成 text 对象而消失**。自动改名统一用 `ggbauto1` 这类形式。

### 命令改名的三种形态（实测）

| 写法 | 结果 |
|---|---|
| `Rename("s","x")` | ❌ 引号让 GeoGebra 当字符串字面量，**新建一个 text 对象**，原线段纹丝不动（且类型变 text，极易误判成"改名成功"） |
| `Rename(s,"x")` | ✅ 对象名不加引号才对 |
| `api.renameObject("s","x")` | ✅ 最直接，**本项目采用**，每次改名后回读对象列表校验 |

### 样式命令的返回值

见[第一节第 2 条](#2-样式命令被误判为失败--整板回滚)。

### 精简 TikZ 的选项块

`\begin{axis}[...]` 的选项块必须**连同选项一起剥掉**，否则 `[x=1cm,y=1cm, axis lines=middle, ...]` 会残留进产物。`\begin{tikzpicture}[...]` 同理。正确正则：

```ts
/\\begin\{axis\}(\[[\s\S]*?\])?([\s\S]*?)\\end\{axis\}/
```

### `toPgfExpression` 的括号

`x^(2)` → `(\x)^(2)`，且要先替换 `x^(n)` 再替换独立的 `x`，最后 `e.replace(/\\\\x/g, "\\x")` 收敛（否则会产出 `\\x`）。

## 四、KaTeX 单份渲染与公式复制

KaTeX 默认的 `htmlAndMathml` 会额外输出一层被 CSS 裁到 1px 的 MathML，它仍参与浏览器的文本选择，导致复制出的公式变成「`2 2`」「`B D E BDE`」「`x = A E x=AE`」这类重复字符。

修复：`katex.renderToString(..., { output: "html" })` **只输出一份 HTML**。渲染正则另加保护：行内公式不允许跨空行、长度上限 400 字符，避免流式输出时未闭合的 `$` 吞掉整段正文。

**残留限制**：即使只输出一份 HTML，KaTeX 用 CSS 定位排版分式、根号、上下标，**直接框选页面复制**仍可能得到带换行的排版碎片。需要干净可编辑的公式文本时，点回复下方的「复制原文」，拿到的是未经渲染的 Markdown（公式保持 `$...$` / `$$...$$`）。剪贴板 API 被浏览器拒绝时自动降级到临时 `textarea` + `execCommand`。

## 五、画板尺寸自适应的实现

GeoGebra 注入时固定了 canvas 的像素尺寸，窗口缩放、顶栏/导出按钮折行、提示条出现或分栏拖动后**不会跟随**，旧 canvas 会盖住聊天区。

处理方式：

1. 用 `ResizeObserver` 监听容器 → 清理 GeoGebra 写入的 inline 尺寸 → 调用 `applet.setSize()` 重算内部视图 → 派发 `resize` 事件。
2. 容器宽度用 `width: 100% !important` 锁死为面板宽度。**必须锁**：GeoGebra 的 resize handler 会往容器写回旧像素宽度，不锁住会形成「容器不缩 → 画板不缩」的死循环。
3. 再加 `overflow: hidden` 兜底。

拖动分栏时盖一层临时遮罩，避免 GeoGebra 内部的 canvas / iframe 截走指针事件。

## 六、云函数（llm-proxy）的几类故障

### POST 返回 200 但响应体为空

云函数曾直接把上游 `ReadableStream` 和全部响应头透传，EdgeOne 线上运行时会返回 200 却丢掉 body（本地 `makers dev` 正常，容易漏测）。

修复：只透传 `content-type` / `cache-control` 等安全头，剔除 `transfer-encoding` / `content-length` / `connection`，并用**惰性** `ReadableStream` 包一层上游 body。

> 改动时不要退回 `new Headers(upstream.headers)` + `new Response(upstream.body)`。

### POST 返回 422 `missing field messages`

EdgeOne 运行时可能把 `context.request` 直接给成标准 `Request`，其 `body` 是 `ReadableStream`；沿用 `JSON.stringify(req.body)` 会得到 `{}`，上游模型收到空对象就报 `missing field messages`（GET 探测仍正常，容易误判为额度或 Key 问题）。

通用处理器现在优先 `await req.text()`，失败再回退到平台已解析的字符串 / 普通对象；Cloudflare 侧仍由 `functions/llm-proxy.ts` 预读 body，两条路径都覆盖。

### 两个平台的差异（只有这一处）

| | EdgeOne 云函数 | Cloudflare Pages Functions |
|---|---|---|
| 入口 | `cloud-functions/llm-proxy/index.ts` → `/llm-proxy` | `functions/llm-proxy.ts` → `/llm-proxy`，内部复用同一份通用处理器 |
| 请求体 | 可能是已解析的字符串 / 对象，也可能是标准 `Request`（`ReadableStream`） | 标准 `Request`，body 是 `ReadableStream` |
| 处理 | 通用处理器优先 `await req.text()`，失败再回退 `req.body` | 适配层先 `await request.text()` 再交给通用处理器；不做这步所有 POST 都会变成空 body |
| 环境变量 | `edgeone makers env set KEY VALUE -e production` | `wrangler pages secret bulk` 或控制台 |

白名单、CORS、SSE 惰性流包装、5.5MB 请求体保护全部复用同一份代码；Cloudflare 侧额外用 `content-length` 做 6MB 前置拦截。

### 白名单机制

`/llm-proxy` 只允许转发到 `ALLOWED_HOSTS` 里的域名，否则返回 403 `target host not allowed`。**前端能选 ≠ 云函数放行** —— 新增服务商预设时必须同步改 `cloud-functions/llm-proxy/index.ts` 的 `ALLOWED_HOSTS`（本轮新增 `open.bigmodel.cn`）。

### 部署后的自检清单

`GET /llm-proxy` 返回 `{"serverKey":true,"provider":"custom","model":"deepseek-flash"}` → POST 文本有完整 body、SSE 能吐 `data:`、带图能读出颜色 → `/geogebra/deployggb.js` 与 10MB 的 `*.cache.js` 都 200 → 四种导出与「打开 .ggb」在新域下可用 → 回 EdgeOne 站回归一次确认没被影响。

## 七、提示词：内置的 GeoGebra 指令速查与三条硬规则

系统提示词里内置了一份 GeoGebra 官方指令速查（点 / 线段 / 直线射线 / 圆弧扇形 / 角与平分线 / 三角形四心 / 交点测量向量 / 变换 / 样式命令），以及三条硬规则：

- **依赖顺序**：先定义坐标已知的点，再画基本图元，最后生成依赖它们的派生对象；被依赖的对象必须先定义。
- **封闭多边形用 `Segment` 逐边绘制**（`Segment(A,B)`、`Segment(B,C)`、`Segment(C,A)`），不用 `Polygon`——`Polygon` 的填充与顶点顺序在导出 TikZ 时容易丢失。
- **要设置样式的对象必须显式命名**（`s = Segment(A,B)` 再 `SetLineStyle(s,1)`）。否则模型不知道自动分配的名字叫什么，一旦撞上函数名 `f(x)=…` 还会把线段顶掉。

这些指令语法都是 GeoGebra 官方文档里的公开事实（命令名 + 参数顺序），与任何第三方实现无关。

工具返回值里的 `notes` 会告诉模型哪些对象被自动重命名 / 覆盖：

```ts
const notes: string[] = [];
if (r.renamed?.length) notes.push(`为避免同名覆盖，已自动重命名：${r.renamed.join("、")}`);
if (r.overwritten?.length) notes.push(`这些名字此前已存在并被覆盖：${r.overwritten.join("、")}`);
```

## 八、`.ggb` 导出补缩略图

网页 applet 的 `getBase64()` 产物默认不带 `geogebra_thumbnail.png`，导致部分 GeoGebra 桌面版打不开。

处理：先校验 ZIP 文件头，再**纯字节追加**缩略图条目（不解压原条目、不重写 CRC），失败自动回退引擎原始产物，不会让导出失败。

实测产物 ZIP / CRC 全部有效，且能被 GeoGebra 引擎完整回载。

## 九、端到端实测方法（CDP 拦截 + 伪造工具调用）

用 Chrome DevTools Protocol 驱动无头浏览器，**拦截 `*llm-proxy*`**，自己扮演模型服务，从而端到端验证「模型 → 工具 → 画板 → 导出」整条链路：

1. `Fetch.enable` 只拦 `*llm-proxy*`；GET 返回探测 JSON。
2. POST 喂**伪造的工具调用 SSE**（`delta.tool_calls[].function.arguments` + `finish_reason:"tool_calls"`）。
3. 工具执行后第二次 POST 再喂纯文本 SSE。
4. 用 `URL.createObjectURL` 猴补丁捕获导出的 Blob 文本。
5. 读取 `window.ggbApplet.getAllObjectNames()` 核对对象数、类型、线型、颜色。

**命令序列要刻意包含历史 bug 的触发条件**：

```js
const COMMANDS = [
  "A=(0,0)", "B=(4,0)", "C=(2,3)",
  "Segment(A,B)", "Segment(B,C)", "Segment(C,A)",   // 自动命名为 f/g/h
  "SetLineStyle(f,1)",                              // f 会被后面的函数顶掉
  "SetColor(g,\"#FF0000\")",
  "c=Circle(C,1.5)",
  "f(x)=x^2/3-2",                                   // ← 同名覆盖触发点
  "X=(50,50)", "Y=(60,50)", "far=Segment(X,Y)",     // 视口外，验证覆盖校验补齐
];
```

**期望结果**：11 个对象全部保留；原 `f` 线段被改名为 `ggbauto1` 且虚线 `style=1` 不丢；红色线段 `color=#FF0000` 不丢；完整版与精简版 TikZ 都含 `(50,50)--(60,50)`。

## 十一、运维踩坑

### Git Bash 下 `node -e` 的 `/tmp` 路径

Git Bash 里 `/tmp` 实际是 `C:\Users\<user>\AppData\Local\Temp`，但 `node -e` 里的 `/tmp/x.json` 会被 Node 当成 Windows 路径 `C:\tmp\x.json` 而找不到文件（**bash 重定向的 `/tmp` 与 Node 里的 `/tmp` 不是一回事**）。

解法：用 `cygpath -w /tmp` 转成 Windows 路径再传给 Node，或让 bash 重定向后再传 Windows 绝对路径。

### 代理端口失效导致 push 502

环境变量里的代理端口（`http_proxy=http://127.0.0.1:59714`）会失效，此时 `git push` 报 `CONNECT tunnel failed, response 502`，而 `curl https://github.com/` 返回 000。

真实代理在**系统 WinINET 设置**里：

```powershell
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyServer
```

本机是 `127.0.0.1:7890`。修复：push 时显式覆盖：

```bash
GIT_CONFIG_NOSYSTEM=1 https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890 \
  git -c credential.helper=store -c http.postBuffer=1048576 push origin main
```

### Cloudflare 403 `error code: 1010`

Cloudflare 防火墙按 User-Agent 拦截 Python urllib，**非应用故障**。用 curl（正常 UA）复测即可。

### 构建与预览的文件锁

`vite preview` 占用 `dist` 会导致 build 写文件被锁。先停 preview 再 build。

### Node 脚本挂起

数据已写出但进程不退出，通常是 WebSocket 未关闭。脚本末尾补 `ws.close(); process.exit(0);`。
